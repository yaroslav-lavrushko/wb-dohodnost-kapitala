# Доходность вложенного капитала по товарам WB

Все деньги считает программа `wb-capital` (репозиторий yaroslav-lavrushko/wb-dohodnost-kapitala) — детерминированно,
одинаково и без Claude. Задача Claude: проверить вход, запустить, прочитать результат и написать «что это значит и что делать».

## Установка (один раз)

```
pip install "git+https://github.com/yaroslav-lavrushko/wb-dohodnost-kapitala"
```

Если данные нельзя передавать в облако — предложить веб-версию (https://yaroslav-lavrushko.github.io/wb-dohodnost-kapitala/):
она считает в браузере пользователя, файлы не покидают его компьютер.

## Вход

| Что | Откуда | Обязательно |
|---|---|---|
| Еженедельные детализации WB (xlsx или zip) | ЛК WB → Финансовые отчёты → детализация | да |
| Каталог себестоимости по поставкам | лист «Каталог (себестоимость)»: «Номер поставки», «Название товара», «Себестоимость» | да |
| Остатки — все места хранения | WB «Остатки по складам», выгрузка своего склада или фулфилмента (артикул / код WB + количество; «Склад», «Дата» — если есть) | для доходности — да |

Тип файла определяется по колонкам. Дата снимка остатков — в имени файла, в колонке «Дата» или `--stock "файл.xlsx@ГГГГ-ММ-ДД"`.

## Шаги

1. Сложить выгрузки в одну папку и запустить:
   ```
   wb-capital --in <папка> --out <папка-отчёта> [--commission-pp 3]
   ```
   Код выхода 2 — вход не подходит; в папке отчёта `ОШИБКИ-входных-данных.txt` со списком недостающих колонок по
   каждому файлу. Сказать пользователю, какие колонки нужны и где их взять, — не чинить молча.
2. До выводов проверить лист «Проверки» в Excel: «Сумма по артикулам = итог кабинета» — «да»; как найдены цены
   себестоимости (много «по первой поставке» или «нет в каталоге» → дописать `aliases.json` и перезапустить);
   предупреждения об остатках (без даты, строки без заголовка, снимок вне периода).
3. Написать выводы поверх листа «Итог» (коротко, красное первым):
   - 🔴 «выводить» с наибольшими деньгами в остатке — сколько денег высвобождается;
   - 🟡 «сократить закупку» — лишний запас в рублях и что не дозаказывать;
   - 🟡 «держать» и «нет продаж в периоде» — цена, реклама, дата прихода;
   - 🟢 «развивать» — куда докладывать деньги в первую очередь;
   - сценарий комиссии и честная оговорка о качестве данных (один снимок остатков, тестовые остатки, пропуски).
4. Интерактивный HTML-отчёт можно отдать как есть: ползунки порогов и комиссии, карточка товара, фильтры.

## Правила расчёта

- P&L товара = к перечислению за товар (продажи − возвраты) + компенсации WB − логистика − хранение − штрафы −
  реклама и прочие удержания − себестоимость (− налог, если задан). Расходы без артикула разносятся по выручке
  (хранение и приёмка — по деньгам в остатке); сумма по товарам всегда равна итогу кабинета.
- Себестоимость — по паре «поставка × артикул»: точная поставка → ближайшая более ранняя → первая в каталоге.
- Капитал — весь товар во всех местах хранения + в пути, по цене последней поставки. Одна дата — места складываются,
  одно место на разные даты — среднее. Товар = код WB.
- Доходность = прибыль за период × 365 / дней ÷ капитал. Пороги по умолчанию: > 25% развивать (если запас > 90 дней
  и лишнего ≥ 10 000 ₽ — сократить закупку), < 8% выводить, между — держать. Пороги — в `config.json`, менять только
  с согласия владельца данных.
- `--test-stock-days N` подставляет ТЕСТОВЫЙ запас товарам без остатка — только для проверки, в отчёте помечено «ТЕСТ».
